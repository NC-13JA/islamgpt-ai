# IslamGPT AI

مساعد ذكي لأندرويد للتحكم المساعد بالهاتف عبر الأوامر النصية والصوتية وواجهة API.

## الحالة
نسخة قابلة للبناء والتطوير: واجهة محادثة، إعداد API محلي، فحص تحديثات GitHub، تنزيل APK وتثبيته بموافقة Android، وأوامر هاتف محلية محدودة عبر خدمة إمكانية الوصول الاختيارية.

## المتطلبات
- Android Studio حديث وJDK 17
- Android SDK 35
- Android 8.0+ (API 26)
- اتصال إنترنت لاستخدام API

## البناء
افتح المستودع في Android Studio، ثم شغّل `app > Tasks > build > assembleDebug`.
ملف APK: `app/build/outputs/apk/debug/app-debug.apk`.

## الإعداد
1. أدخل عنوان API متوافقًا مع OpenAI Chat Completions، ومفتاح API، واسم النموذج.
2. لا تضع المفتاح في ملفات المصدر أو المستودع.
3. ابدأ الخدمة من زر «تشغيل المساعد».
4. فعّل خدمة إمكانية الوصول يدويًا إن أردت التفاعل مع عناصر الواجهة.
5. زر الصوت يستخدم التعرف على الكلام عند الطلب. كلمة تنبيه دائمة ليست مفعلة بعد.

## الأمان والقيود
- الخدمة الأمامية لا تضمن التشغيل الأبدي؛ قد تفرض الشركة المصنعة قيود البطارية.
- تطبيق عادي لا يستطيع قتل عمليات التطبيقات الأخرى بحرية. الإيقاف القسري وتغييرات النظام الحساسة قد تتطلب ADB أو صلاحيات النظام أو الروت.
- خدمة إمكانية الوصول صلاحية حساسة، فعّلها فقط عند فهم ما تسمح به.
- مفتاح API محفوظ محليًا في تفضيلات التطبيق في هذه النسخة؛ استخدم مفتاحًا محدود الميزانية ولا تشارك الجهاز.
- تُرسل الرسائل التي تدخلها إلى عنوان API المحدد.

## خارطة الطريق
- كلمة تنبيه قابلة للتخصيص مع تشغيل/إيقاف صوتي.
- أوامر آمنة وتأكيد قبل الإجراءات الحساسة.
- اختيار التطبيقات المسموح بها وسجل تنفيذ.
- ADB اختياري عبر حاسوب موثوق، ودراسة الروت كخيار منفصل.
- بناء APK Debug عبر GitHub Actions.\n- نشر تحديثات Release موقعة: يتطلب إعداد مفتاح توقيع ثابت في أسرار المستودع، حتى يقبل Android تحديث التطبيق دون تعارض في التوقيع.


## نشر التحديثات التلقائية

يحتوي `.github/workflows/release.yml` على سير عمل ينشر APK جديدًا في GitHub Releases بعد كل تحديث على `main`، **لكن النشر يتجاوز خطوة الإصدار حتى تُضاف أسرار التوقيع الثابتة**. لا تضع ملف المفتاح أو كلمات مروره في المستودع.

1. أنشئ مفتاح توقيع Android خاصًا واحتفظ بنسخة احتياطية آمنة منه.
2. في GitHub افتح `Settings → Secrets and variables → Actions` وأضف الأسرار التالية:
   - `ANDROID_KEYSTORE_BASE64`: محتوى ملف keystore بعد ترميزه Base64.
   - `ANDROID_KEYSTORE_PASSWORD`: كلمة مرور keystore.
   - `ANDROID_KEY_ALIAS`: اسم المفتاح داخل keystore.
   - `ANDROID_KEY_PASSWORD`: كلمة مرور المفتاح.
3. بعد ذلك سيبني سير العمل APK موقّعًا وينشره في Releases، وسيتمكن التطبيق من اكتشافه وتنزيله.

**مهم:** فقدان مفتاح التوقيع يمنع نشر تحديثات فوق النسخة الموقعة به. وإذا كانت النسخة المثبتة حاليًا موقعة بمفتاح Debug مختلف، فقد تحتاج إلى إزالة تلك النسخة وتثبيت أول إصدار موقّع جديد يدويًا؛ هذا قد يمسح إعدادات التطبيق المحلية.
